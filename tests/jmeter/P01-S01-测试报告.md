### 2.3 判定与限制

本次 P-01 基线通过，所有指标均优于当前验收目标。

但当前首页接口只返回约 29 字节的空数据响应：


因此数据库查询、JSON 序列化、商品图片、缓存未命中和大响应体等真实成本没有被覆盖。补充接近生产量级的市场、分类、商品和专区数据后，应重新执行 20、50、100 并发阶梯测试，才能形成容量结论。

## 3. S-01 商城接口安全性检查

### 3.1 通过项

| 检查项 | 实际结果 |
| --- | --- |
| 账号受保护接口匿名访问 | HTTP 401，包含 unauthorized |
| 账号受保护接口伪造 Token | HTTP 401，包含 invalid_token |
| 商城受保护接口匿名访问 | HTTP 401，包含 unauthorized |
| 商城受保护接口伪造 Token | HTTP 401，包含 invalid_token |
| 商城敏感 Actuator /actuator/env | HTTP 404，未泄露环境变量 |

匿名拒绝响应同时包含 Cache-Control: no-store、X-Content-Type-Options: nosniff 和 X-Frame-Options: DENY。

### 3.2 风险项

| 风险 | 级别 | 证据 | 建议 |
| --- | --- | --- | --- |
| 账号服务和商城服务反射任意 CORS Origin，同时允许 Credentials | 高 | 对 https://evil.example 返回对应的 Access-Control-Allow-Origin 和 Access-Control-Allow-Credentials: true | 配置明确域名白名单；禁止任意来源携带凭证 |
| 声明为 POST 的商品查询接口接受 GET | 中 | GET /v1/app/market/goods/query 返回 HTTP 200 | 统一 Controller 映射，未允许的方法返回 405 |
| 非法数字参数未被拒绝 | 中 | pagesize=abc 返回 HTTP 200 和 success=true | 增加参数绑定异常处理和 Bean Validation，返回 400 |
| 必填参数缺失未被拒绝 | 中 | 商品详情缺少 pkey 仍返回 HTTP 200 和 success=true | 对必填参数做非空、范围和类型校验 |

CORS 风险在账号服务和商城服务各产生一条失败样本，因此 S-01 共计 5 个失败样本。

### 3.3 代码配置补充风险

商城安全配置目前对 /actuator/** 使用了公开匹配，并公开 /server/resetCache、/server/changeLogLevel/**。本次没有调用后两个接口，因为它们可能修改服务器状态。

建议：

1. 只公开 /actuator/info 和必要的健康端点。
2. 删除 /server/resetCache、/server/changeLogLevel/** 的匿名访问。
3. 通过内网、管理身份或运维网关保护管理端点。

## 4. 复测要求

修复 S-01 风险后重新执行 04-s01-api-security.jmx，目标为 10/10 通过、错误率 0%。

补充真实业务数据后，P-01 推荐按以下顺序执行：

1. 20 并发 × 5 分钟：稳定性基线。
2. 50 并发 × 10 分钟：预期业务峰值。
3. 100 并发 × 10 分钟：容量余量。
4. 逐级增加并发：定位错误率超过 1% 或 P95 超过 1.5 秒的拐点。

每一级测试期间都应同步采集 JVM 堆、GC、数据库连接池、MySQL 慢查询、Redis 和容器 CPU/内存指标。
